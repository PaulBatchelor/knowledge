#! dz $
The abstraction layers for the word machine are delicate
because I've decided I want the msgpack parser to be
part of the "host" layer. When a byte is sent to the
word machine, it sort of oscillates between the host
and word machine abstraction boundaries.
Once the word is sent into the machine, it jumps back "up"
into the layer that has the host. There, the host checks
if the word has been filled, and extracts and processes it.
The word buffer also will need to be cleared.
---
Processing the word is only a matter of checking the first
bytes to determine if it is a system command. The system
command components are then extracted, and those bits
are processed. The only edge case implemented will be $(0, 0)$,
which will set the sonilo VM rw register to be a magick number.

@19:51 working out the msgpack bytes #timelog:00:41:14
#! dz $
I want to write a program that will write {\tt 12344321} and {\tt 88888888}
to the terminal. Begin a new message. Set the word, then print it. Do it
again. End the message.
---
Possibly set another magick word like {\tt 22222222} and have the test harness
print word program print that word, just to double check and make sure
it is the same register being set.
---
System commands $s(0, 1)$ and $s(0, 2)$ can be used for starting and ending
the message.
---
Might be a good idea to print the bytes for $s(0, 2)$ just to show it is
possible to append any word to the word buffer.
---
Define {\tt BEGIN} as $s(0,1)$, which would be the
msgpack payload {\tt 0x8100cc01}.
Similarly, {\tt END} would be $s(0,2)$, or {\tt 0x8100cc02}.
---
32-bit data instruction is composed of two words, the header word
and the data word. The header word describes a 1-sized fix map,
but with a 1-sized fixstr for the key, and a leading for the 32-bit int.
---
Fixmap is {\tt 0x81}. The key to be used is '!', which is {\tt 0x21} in ASCII.
A single-character fixstr is {\tt 0xA1}, making the key {\tt 0xA121}.
Finally, the 32-bit unsigned integer has the byte {\tt 0xCE}.
Putting it all together, the word is {\tt 0x81A121CE}. The next word
that follows is an arbitrary 32-bit word.
---
confirmed that this works. wrote the hex bytes to a file, converted
to actual bytes using xxd, then parsed with the msgpack parser I shipped
with mnolth. It is indeed valid msgpack.
---
The final missing piece are the system commands used split up the 32-bit
word into two shorts.
The prefix of this message is going to be a fixmap with the key of '1'.
The remaining two bytes will be interpretted as as a u16 in big-endian
encoding like how msgpack does it.
---
So that first half of the word is {\tt 8101}, then the last two bytes
are read and appended to the word register.
---
So, if I had two half-word (short) instructions $hw(1234)$ and $hw(5678)$,
I would expect the RW register to be $12345678$. If I had another instruction
following that went $hw(9999)$, I would expect the RW register to be $56789999$.
---
To be enormously explicit, the hex words to produce $12345678$ in the word
register would look like {\tt 0x81011234} and {\tt 0x81015678}.
To encode the END command into the RW register, you'd write it as {\tt 0x81018100}
and {\tt 8101CC02}.
